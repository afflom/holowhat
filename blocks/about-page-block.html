Why a Dev Environment in the Browser?

This article was written without the assitance of AI, and proofread by Wife.

I hope the openness and accessibility of source code and data in one environment inspires new ways of working that are more flow-based. A Figma-like editor acting on live code. A button click from an app triggering a debug window to a backend function. Right clicking the UI opening the source code for a block. How can coding become more immediate and ultimately more enjoyable?


What is Playground?

It's a website for creating collaborative worlds made up of web components and JSON data.

To publish blocks from a world, just include the playground.js script on a web page and write block tags into the HTML.

You can even edit the blocks that make up the world canvas itself, to create new tools for yourself and others. So far there is:

  • a canvas and minimap for navigating
  • a code editor for writing blocks
  • a rudimentary database editor
  • an API client
  • and settings for fonts and themes

What's next?

The goal is to create a general purpose programming environment for the web. That means editing HTML, CSS and JavaScript as well as hosting files and writing secure backend logic, even configuring infrastructure. Phew, that's a mouthful.


Acknowledgements

There are some noteworthy influences to this project, the first being the Lively Kernel created by Dan Ingalls, and the Smalltalk programming language, of which there are many flavors, but I think that Cuis Smalltalk is the most representitive because it gave me the "oh that's nice" feeling while learning how to use it. I also credit GameMaker 8.1, the first programming environment I ever worked in, and a wonderful implementation of a gentle slope to skill attainment. To refresh my memory, I created a simple pong game using the drag and drop blocks and found it to be just as enjoyable today.

In the early versions of Playground, I attempted to write a websocket layer for collaborative programming. Those quite poor attempts are open-sourced on the Playground 1.0 GitHub page. When a friend directed me to the Ink & Switch lab and Automerge library, three remarkable things happened. First, I found a library that made collaborative editing much easier. Second, I found a trove of essays and talks that helped me build a vocabulary for my somewhat vague feelings about what's wrong with software development today and how it might be made better. Third, I joined a Zoom call where Alan Kay and Dan Ingalls showed up! I even got to have a 30-second conversation with Dan. He said I have it a lot easier today because the web browser does so much more, and when he created the Lively Kernel he had to write his own SVG renderer.

Another challenge in early versions was the block framework. I tried to write a frontend framework, which ended up working very poorly. Then I discovered Alpine.js, and immediately felt that it would enable a clean looking syntax for the blocks. It has the added benefit of working without a compilation, which is important for editing in-browser. I don't know if blocks will always depend on Alpine.js, but there wouldn't be a usable version of Playground today without it.
